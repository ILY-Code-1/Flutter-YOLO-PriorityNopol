Desain Basis Data NoSQL (Firebase Firestore) — PrioScan

PrioScan — Priority Vehicle Scanner using YOLOv8. Dokumen ini menjelaskan struktur penyimpanan data deteksi kendaraan prioritas (Ambulance, Police, Fire Truck) beserta hasil pembacaan plat nomornya pada Cloud Firestore.

1. Desain Model NoSQL

Aplikasi PrioScan menerapkan strategi pemodelan flat collection dengan pendekatan Embedding (denormalisasi). Seluruh data satu kali deteksi disimpan utuh dalam satu dokumen pada koleksi vehicle_detection — tanpa sub-koleksi maupun referensi antar dokumen.

Alasan pemilihan strategi:

  • Akses baca tunggal. Halaman Riwayat Deteksi (HistoryPage) maupun Hasil Deteksi (ResultView) selalu menampilkan seluruh atribut satu deteksi sekaligus (jenis kendaraan, nomor polisi, gambar, confidence, tanggal). Embedding membuat satu kali baca dokumen sudah cukup, tanpa join ataupun lookup tambahan.
  • Tidak ada relasi kompleks. Domain aplikasi hanya memiliki satu jenis entitas inti (catatan deteksi). Jenis kendaraan hanya berupa nilai enumerasi tetap (Ambulance, Police, Fire Truck), sehingga tidak perlu koleksi master terpisah.
  • Real-time stream. MainController menggunakan .snapshots() dengan orderBy('detectedAt', descending: true). Struktur flat memudahkan pengurutan dan filter kategori di sisi klien.
  • Gambar tertanam. Field imageBase64 menyimpan gambar dalam bentuk data URI base64 langsung di dokumen, sehingga riwayat tetap dapat menampilkan foto tanpa memerlukan pengambilan berkas terpisah.

Contoh konkret: ketika pengguna menekan SUBMIT, DetectionController.submit() membuat satu dokumen dengan ID = DateTime.now().millisecondsSinceEpoch (mis. "1733740800000") di koleksi vehicle_detection.

2. Struktur Koleksi

  • 📁 vehicle_detection (koleksi root)
    • 📄 {detectionId}  — contoh ID: "1733740800000" (epoch milidetik)
      • vehicleType : string  → "Ambulance"
      • plateNumber : string  → "B 1234 XYZ"
      • imageBase64 : string  → "data:image/jpeg;base64,/9j/4AAQ..."
      • detectedAt : timestamp  → 9 Jun 2026, 10:00
      • confidence : number  → 0.93

Tidak terdapat sub-koleksi maupun referensi ID antar dokumen. Setiap dokumen berdiri sendiri (self-contained) dan mewakili satu peristiwa deteksi.
